# Part 1: How it works

Read this part when you get stuck. It has the answer to almost every question you will have.

## You type the code yourself

Your Python file is mostly empty. That is on purpose.

Every line you need is printed in Part 2 of this guide, and you type it into the file by hand. Typing it is the point. It is how the shape of Python gets into your hands instead of just past your eyes.

You will make mistakes doing this. Everyone does. Finding them is most of what programming is.

## Blocks

A program is not just a list of lines. Lines get grouped, and a group of lines is called a block.

Here is the idea without any robot in it:

```
if it is raining:
    take an umbrella
    wear boots
go to school
```

"Take an umbrella" and "wear boots" are a block. They belong to the rain. If it is not raining you skip both of them. "Go to school" is not in the block, so it happens either way.

Python shows blocks by pushing them to the right:

- A line that ends with a colon starts a block.
- The lines pushed to the right below it are the block.
- The first line that comes back to the left ends the block.

A block can hold another block. That is normal, and your file does it.

**Thonny does the pushing for you.** End a line with a colon, press Enter, and the cursor is already sitting where the block starts. It keeps you there, line after line, until you tell it otherwise. To come back out of a block, press Backspace once.

So when you type code out of this guide, you mostly do not have to think about the spacing at all.

## Setting up

The first thing your program does is build what it needs:

```
alvik = ArduinoAlvik()
alvik.begin()
sb = SuperBot(alvik)
gamepad = RobotGamepad(alvik)
```

Each of those lines makes one thing and gives it a name. Programmers call those things objects. An object is a bundle of information plus the commands that go with it — the robot is an object, the gamepad is an object.

- `alvik` is the robot itself. `ArduinoAlvik()` builds it and `begin()` starts it running.
- `sb` is a SuperBot. Think of it as an Iron Man suit for the Alvik. The robot climbs inside and comes out able to do things it cannot do on its own. This class built the suit. Every project puts it on, and each project uses a few more of its powers. Today you use exactly one.
- `gamepad` is the controller. Building it starts the robot's own WiFi network and then waits. The lights blink yellow until your browser connects, then turn green.

The order matters. `alvik` has to exist *and* be running before the other two lines, because both of them are handed `alvik` to work with.

When you run the program, the Shell prints a version number for each part of the suit as it loads. That is normal. It is how you know which version of the code your robot is running.

## The main loop

Real robots do not run once and stop. They loop. They check their sensors over and over, hundreds of times a second.

Your loop is already in the file:

```
while not (sb.held('cancel') or gamepad.held('options')):
```

That line ends in a colon, so everything below it that is pushed to the right is the loop's block. It runs again and again.

That line is also your stop button. Touch Cancel on the robot, or press Options on the gamepad, and the loop ends on its own. You do not need Thonny's Stop button.

`held()` answers one question: is that button down right now? The robot's own touch pads are `'up'`, `'down'`, `'left'`, `'right'`, `'ok'` and `'cancel'`. The gamepad answers to `held()` too, using its own button names.

## Ask the gamepad for fresh data

The first line inside the loop is this:

```
gamepad.update()
```

Think of it like checking your phone. If you never refresh, you never see the new text. `gamepad.update()` asks the controller which buttons are down right now. Leave it out and your robot is flying blind.

## Making choices

Now the robot has the button data. It has to decide what to do. You write rules.

Here is the shape, again with no robot in it:

```
if temperature > 90:
    print("wear shorts")
elif temperature > 60:
    print("wear jeans")
else:
    print("wear a coat")
```

Read it top to bottom, the way Python does.

- `if` is the first rule. Python checks it first.
- `elif` is short for "else if." Python only checks it when every rule above it was false.
- `else` is the catch-all. It runs when nothing above it matched.

Say the temperature is 95. Python checks the first rule, it is true, so it prints "wear shorts" and it is done. It never even looks at the other two.

Only ONE of those blocks runs. That is the whole point of writing them together. A group of rules built this way is called a chain, and that word shows up again in Part 2.

If you wrote three separate `if` statements instead, more than one could run, and with lights that means two colors fighting over the same LED.

## Mixing colors

Your robot has two RGB LEDs on its top board, one on each side of the touch buttons. In code they are `alvik.left_led` and `alvik.right_led`.

Each one mixes red, green, and blue. You pass a 1 to turn a color on and a 0 to turn it off. These examples all use the left LED. The right one works exactly the same way.

```
alvik.left_led.set_color(1, 0, 0)   # red
alvik.left_led.set_color(0, 1, 0)   # green
alvik.left_led.set_color(0, 0, 1)   # blue
alvik.left_led.set_color(1, 1, 1)   # white, all three at once
alvik.left_led.set_color(0, 0, 0)   # off
```

Two colors at once make a new one. Red plus blue is magenta. Green plus blue is cyan. You will want those for the flex.

## The finally block

At the bottom of your file is a `finally:` block.

Code inside `finally` always runs. It runs when the program ends normally. It runs when you hit Stop. It runs even if your code crashes.

That matters. Without it the robot freezes in whatever state it was in. Lights stuck on. In later projects, with motors, wheels stuck spinning.

So every program in this class cleans up in `finally`.

One line is already written for you: `alvik.stop()`. Always call it, in every project. It shuts down the robot software and frees the WiFi network. Skip it and the robot can hang, and then you have to restart it to get going again.

# Part 2: Do the work

## Step 1: Set up

1. Turn on your Alvik robot.
2. Open `p01_gamepad_lights.py` in Thonny and save your own copy to the robot, as described at the top of this guide.
3. Run the program. Thonny prints your robot's WiFi name in the Shell.
4. Connect your Mac to that WiFi network. The password is `password`.
5. Open `http://192.168.4.1` in Chrome. Keep that Chrome window in front for the whole project. Chrome blocks gamepad input to any window that is not focused, so clicking over to Thonny makes your buttons stop working.
6. Pair your PS5 controller to the Mac over Bluetooth. The robot's LEDs turn green when it connects.

## Step 2: Type in WORK 1

These four lines build the robot, start it, and build the two things that need it. Nothing else in your program can work until they run.

Find the `# WORK 1` comment and type them underneath it. They start at the left edge:

```
alvik = ArduinoAlvik()
alvik.begin()
sb = SuperBot(alvik)
gamepad = RobotGamepad(alvik)
```

Run it. You should get version numbers in the Shell, a WiFi name, and blinking yellow lights that turn green once the browser connects. If you get that far, your setup is right.

## Step 3: Type in WORK 2

This is the chain from Making choices, with buttons instead of temperatures. It asks four questions in order and only one of them wins:

- Is X held? Both lights go blue.
- If not, is CIRCLE held? Both go red.
- If not, is TRIANGLE held? Both go green.
- If none of those, both go white.

White means "running, waiting for a button." It is how you tell a robot that is waiting from a robot that is frozen.

Find the `# WORK 2` comment, inside the loop, and type this underneath it:

```
if gamepad.held('cross'):
    alvik.left_led.set_color(0, 0, 1)
    alvik.right_led.set_color(0, 0, 1)
elif gamepad.held('circle'):
    alvik.left_led.set_color(1, 0, 0)
    alvik.right_led.set_color(1, 0, 0)
elif gamepad.held('triangle'):
    alvik.left_led.set_color(0, 1, 0)
    alvik.right_led.set_color(0, 1, 0)
else:
    alvik.left_led.set_color(1, 1, 1)
    alvik.right_led.set_color(1, 1, 1)
```

Each `set_color()` pair is a block belonging to the rule above it, so Thonny will already have moved you to the right after each colon. When you finish a pair and need to type the next `elif`, press Backspace once to come back out.

Run it. Hold X for blue, CIRCLE for red, TRIANGLE for green, let go for white.

## Step 4: Type in WORK 3

This is the shutdown. It flashes both lights red for half a second, then turns them off. The flash is proof that the cleanup actually ran — a silent stop looks exactly like a crash, and you want to tell them apart.

Find the `# WORK 3` comment, inside `finally:`, and type these underneath it. They go above the `alvik.stop()` line that is already there. Leave that line alone:

```
alvik.left_led.set_color(1, 0, 0)
alvik.right_led.set_color(1, 0, 0)
time.sleep(0.5)
alvik.left_led.set_color(0, 0, 0)
alvik.right_led.set_color(0, 0, 0)
```

Run it, then press Options. The lights should flash red and go dark.

## Step 5: Worksheet and check off

When you run the finished file, all of this happens in one go. Hold X for blue, CIRCLE for red, TRIANGLE for green, let go for white, then stop and watch the red flash.
