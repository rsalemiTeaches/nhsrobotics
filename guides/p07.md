# Part 1: How it works

Read this part when you get stuck. It has the answer to almost every question you will have.

## What you are building

Back a car up towards a wall and it beeps. Slowly at first. Then faster. Then so fast the beeps run together, and you stop.

Nobody had to read a number. The speed of the beeping *is* the message, and the driver takes it in without looking at anything.

Your robot does the same job with its two top lights instead of a speaker. Far away, a slow blink. Close, a fast one. And while that is going on the screen keeps counting seconds and the sticks keep driving — three things at once, on a robot with one processor that can only ever do one thing at a time.

## The blink you already wrote, and why it will not work here

This is P02, and you wrote it:

```
sb.light_both_leds(1, 0, 0)
time.sleep(0.5)
sb.light_both_leds(0, 0, 0)
time.sleep(0.5)
```

It blinks. It also keeps the robot from checking anything for a whole second every time around.

`time.sleep(0.5)` does exactly what it says. Python sleeps. Nothing runs. The screen does not update, the motors do not change their speed, the sensor is not read, the sticks are not checked.


You never noticed in P02, because a blink was the only thing that project did. The robot did not move, so you did not worry about the motors. It had no distance sensor, so you did not worry about checking it. Now you have to do three things at once, and the first one to fall asleep disables the other two.

There is no version of `sleep()` that fixes this. So from here on, nothing in this project is timed by a sleep. **The robot maintains a clock, and everyone checks it.**

There is one `time.sleep_ms(10)` that gives the robot a moment to think between loops.

## The robot has a clock

When you start running a program, the robot starts a very fast clock. You check how long it has been running with this function:

```
time.ticks_ms()
```

That hands you a number of milliseconds. A millisecond is a thousandth of a second, so this number climbs by 1000 every second. You ask, you get an ever increasing number.

Reading it costs you nothing and stops nothing. Your program carries straight on to the next line.

## Two readings, and the gap between them

One reading on its own is not much use. The number is big and it has been counting since long before you cared about it.

**Two readings tell you how much time went by.** Take one, let things happen, take another, and the gap between them is your answer:

```
before = time.ticks_ms()

# ... whatever happens in between ...

now = time.ticks_ms()
gap = time.ticks_diff(now, before)
```

`ticks_diff(now, before)` hands you the milliseconds between the two readings. If `gap` comes out as `1500`, then a second and a half went by.

It works like a stopwatch. Press it once to mark the start, then look at it as often as you like, without stopping anything to do it.

**Use `ticks_diff()`, never plain subtraction.** The clock counts up to a limit and then rolls over to zero, the way an odometer would. Subtract across that moment and you get a huge negative number, and your timer never fires again for the rest of the run. `ticks_diff()` knows about the rollover. The minus sign does not.

That is the whole tool. Everything left in this project is choosing what to measure from, and what to do once the gap is big enough.

**Take the starting reading before the loop.** Your file has a marked spot for it, above the `while` line, and each WORK step tells you what to put there.

## WORK 1: seconds on the screen

You want the screen to read 0, then 1, then 2 — one number a second.

Mark the start once, above the loop. Then read the clock every time through the loop and measure back to that mark:

```
start_time = time.ticks_ms()

while not sb.held('cancel'):
    now = time.ticks_ms()
    elapsed_ms = time.ticks_diff(now, start_time)
```

Look at where those three lines sit. `start_time` is outside the loop, so it is set once and never changes. The other two are indented inside it, so they run again every time through the loop.

`elapsed_ms` is how long *your program* has been running. It starts at 0 and climbs, whatever the robot's own clock happened to be up to when you pressed run.

Milliseconds are not what you want on a screen, so turn them into whole seconds:

```
while not sb.held('cancel'):
    now = time.ticks_ms()
    elapsed_ms = time.ticks_diff(now, start_time)
    seconds = int(elapsed_ms / MS_PER_SECOND)
```

The `int()` function throws away the fraction, so `seconds` changes only after an entire second has gone by.

**That clicking over is what you are watching for.** Remember the number you saw the time before, and act only when it is different:

```
while not sb.held('cancel'):
    now = time.ticks_ms()
    elapsed_ms = time.ticks_diff(now, start_time)
    seconds = int(elapsed_ms / MS_PER_SECOND)

    if seconds != last_seconds:
        last_seconds = seconds
        sb.update_display("Seconds: ", str(seconds))
```

`!=` means "is not equal to." Read it out loud: if this second is not the one I wrote last time, write it, and remember that I did.

Take that check away and the loop writes `3` to the screen several hundred times before it ever becomes `4` — the same picture, over and over, for nothing.

## WORK 2: the blink

The light has to blink faster the closer the robot gets. That is two questions, and they are much easier apart than together: **how long should the light wait between blinks**, and **has that long gone by yet**.

Work out the waiting time first. You cannot check against a number you do not have.

## From distance to a waiting time

`sb.get_closest_distance()` is the power you used in P04. It reads all five of the front sensors and hands you the smallest number — how much room there is, in centimeters.

You want that number to become a waiting time. Far away, a long wait. Close, a short one. Which is just multiplication:

```
blink_delay = distance * BLINK_MS_PER_CM
```

`BLINK_MS_PER_CM` is 20, so every centimeter of room buys the light 20 more milliseconds of waiting. Fifty centimeters away, the light waits a full second between blinks. Ten centimeters, a fifth of a second. Three centimeters, and it is going faster than you can count.

Nobody worked that 20 out on paper. It was guessed, tried, and changed — the same way you found your numbers in P05. Change it if you do not like how yours feels.

## Why the two limits are there

Your file gives you `BLINK_MS_FASTEST` and `BLINK_MS_SLOWEST`, and two `if` lines pin the answer between them:

```
if blink_delay > BLINK_MS_SLOWEST:
    blink_delay = BLINK_MS_SLOWEST
if blink_delay < BLINK_MS_FASTEST:
    blink_delay = BLINK_MS_FASTEST
```

The fast end is easy to see. Nothing good happens when a light is asked to blink every two milliseconds.

The slow end is doing something you would not guess. Point the robot at open air and none of the five sensors gets an echo back. There is no reading to give you, so `sb.get_closest_distance()` reports 999 — a number chosen to be further away than anything real, so that code asking "is something close?" correctly says no. Multiply 999 by 20 and you have asked the light to wait twenty seconds. Anybody watching would swear the blink was broken.

The slow limit turns that into a blink a little over once a second — a calm heartbeat that says "nothing out there." Same code, no special case.

## Blinking the light at the right moment

Now you have `blink_delay`, so you can go back to the clock.

WORK 1 measured from a mark set once, before the loop, that never moves. The blink measures from a mark that moves — the moment the light last changed. It goes in the same loop, under your WORK 1 lines:

```
while not sb.held('cancel'):

    # ... your WORK 1 lines ...

    if time.ticks_diff(now, last_toggle_time) > blink_delay:
        last_toggle_time = now
```

Read it out loud: if more than `blink_delay` milliseconds have gone by since the light last changed, change it now — and move the mark up to now.

Moving the mark is not optional. Forget that line and the gap only ever grows, so the test is true every time through the loop and the light blinks hundreds of times a second. Your eye reads that as a dim glow that never changes.

**Same tool, two marks.** One is set once and stays put. The other moves every time the light changes. Nothing else about them is different.

Now the light itself. It has to go on, off, on, off, so you remember which it is and turn it into its opposite:

```
led_is_on = not led_is_on
```

`not` turns true into false and false into true. You have already read that word at the top of your loop, in `while not sb.held('cancel')`. Same word, same job.

Then set the LEDs to match:

```
if led_is_on:
    sb.light_both_leds(1, 0, 0)
else:
    sb.light_both_leds(0, 0, 0)
```

## Step 3: Type in WORK 2

The blink.

Two more variables, under the ones you just added:

```
led_is_on = False
last_toggle_time = time.ticks_ms()
```

Then find the `# WORK 2` comment and type this underneath it:

```
distance = sb.get_closest_distance()
blink_delay = distance * BLINK_MS_PER_CM

if blink_delay > BLINK_MS_SLOWEST:
    blink_delay = BLINK_MS_SLOWEST
if blink_delay < BLINK_MS_FASTEST:
    blink_delay = BLINK_MS_FASTEST
```

It uses the same `now` your WORK 1 lines read at the top of the loop. One reading of the clock, two marks measured from it.

Pick the robot up and walk it towards a wall. The blink winds up as you close in.
