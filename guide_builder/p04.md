# Part 1: How it works

Read this part when you get stuck. It has the answer to almost every question you will have.

## Your robot runs on its own now

Everything you have built so far needed you. P01 and P03 needed a laptop, a WiFi network and a controller. P02 needed the USB cable and Thonny's Run button.

This one needs none of it. You put the robot on the floor, turn it on, and walk away.

Every time the robot powers up, it looks for a file named `main.py` and runs whatever is in it. Yours has a line in it already, for the demo the robot shipped with. You replace that line with this one:

```
import workspace.p04
```

`import` means "go find that file and run it." `workspace.p04` is your own `p04.py`, the copy you saved inside the `workspace` folder. So the robot powers up, reads `main.py`, finds your program, and runs it.

**The name has to be exactly right.** `main.py` is looking for `p04.py` inside `workspace`, so that is the only spelling that works. Thonny's Save As will offer you the long name this file already has — change it.

One warning comes with this. From now on, your robot runs your program every time it powers up *or* resets, whether you meant it to or not. A robot on a desk with a charged battery is a robot that can drive off it.

## One loop, two pads, as many laps as you like

Your program sits inside a loop, the way P01, P02 and P03 all did:

```
while not sb.held('cancel'):
```

Hold Cancel and the program ends. That has not changed.

What is new is that this one loop does three jobs at once. Look at what goes inside it:

```
while not sb.held('cancel'):
    sb.light_both_leds(1, 1, 1)
    time.sleep(0.25)
    sb.light_both_leds(0, 0, 0)
    time.sleep(0.25)

    if sb.held('ok'):
        ...the whole trip goes here...
```

One trip around the loop turns the lights on, waits a quarter second, turns them off, waits again, and then asks whether OK is being held.

Nobody holding OK? Nothing happens, and the loop comes back around and flashes again. So the flashing *is* the waiting. The robot is obviously alive and obviously ready, and white means "running, waiting for a button" exactly as it did in P01.

Somebody holding OK? The whole trip runs. Then the loop comes back around and starts flashing again, ready for the next lap.

And because Cancel is checked at the top of every pass, you can quit any time the robot is sitting there flashing. Hold Cancel and you are out.

Hold OK down until the robot moves. The loop only asks about OK twice a second, so a quick tap can land in the middle of a sleep and get missed.

## Ask how far away the wall is

Your robot has five distance sensors across its front. They fire invisible light at whatever is ahead and time how long it takes to bounce back.

Five readings is four more than you want. The SuperBot has a power that boils them down:

```
sb.get_closest_distance()
```

It reads all five, throws out the ones that failed, and hands you the smallest number that is left — the nearest thing in front of the robot, in centimeters. If a wall is 40 centimeters away, you get about 40.

That is the fourth power you have used, after `sb.held()`, `sb.light_both_leds()` and `sb.log_info()`.

Nearest thing means *anything*. A chair leg off to one side, or somebody else's robot, counts as the wall as far as this number is concerned.

## Drive until something happens

Here is a new shape, and you will use it for the rest of the course.

In P03 you set a wheel speed every trip around the loop. This time you set it once:

```
alvik.drive(DRIVE_SPEED_CMS, 0)
```

`drive()` takes a forward speed in centimeters per second and a turning speed. Ten forward, zero turning, so it goes straight. The robot starts rolling and keeps rolling. Nothing stops it.

Then you watch, and you wait:

```
while sb.get_closest_distance() > WALL_THRESHOLD_CM:
    time.sleep(0.03)
```

Read it out loud: while there is more than 15 centimeters of room, do nothing. Check about thirty times a second, and as long as the wall is still far away, keep doing nothing — while the wheels keep turning.

The moment the reading drops below 15, the loop ends. Then you stop:

```
alvik.brake()
time.sleep(0.5)
```

Why the wait? Because `alvik.brake()` does not stop the robot. It *asks* the robot to stop, and then your program runs straight on to the next line while the wheels are still turning. The robot rolls a little further before it settles.

That extra roll is small — about a centimeter at ten centimeters a second — and it would not matter, except that the very next thing you do is ask the robot how far it went. Ask during the roll and the answer comes back short by however much was left to travel. Then the trip home is short by the same amount, every single lap, and after five laps the robot is a hand's width from where it began.

Half a second is long enough for the robot to finish stopping and tell you the truth.

Start it, watch for the thing, stop it, let it settle. None of those steps care how far the wall actually is.

## The robot keeps track of where it has been

You just drove to a wall without knowing how far away it was. Now you have to come back exactly that far. How?

The robot has been keeping count the whole time. Its wheels have counters on them, and from those it works out where it is compared to where it started. That running total is called its pose.

Two commands. The first sets the total back to nothing:

```
alvik.reset_pose(0, 0, 0)
```

Do this right before you drive, the way you would zero a trip meter before a road trip. Otherwise the total still includes the last lap.

The second reads the total back:

```
distance_out, _, _ = alvik.get_pose()
```

That line looks strange, so take it apart. `get_pose()` does not hand back one number. It hands back three at once: how far forward, how far sideways, and how much the robot has turned. The three names on the left catch them, in that order.

You only want the first one. The underscore is a real name you are allowed to use, and it means "something arrives here and I do not need it." You have seen it before without being told — it is the `_` in `for _ in range(3)` from P02. Here there are two of them, for the two numbers you are throwing away.

So `distance_out` ends up holding the distance the robot actually traveled. Not the distance you guessed. The distance it went.

Print it with the power you met in P03:

```
sb.log_info(distance_out)
```

## Turn, drive back, and turn again

Three commands finish the lap.

```
alvik.rotate(180)
```

`rotate()` turns the robot in place by however many degrees you give it. 180 degrees is a half turn, so the robot ends up facing back the way it came.

```
alvik.move(distance_out)
```

`move()` drives forward by however many centimeters you give it. You hand it `distance_out`, the number the pose gave you, and the robot retraces its own trip.

The robot is home now, but it is facing the wrong way — it is looking back down the floor it just drove. Leave it like that and the next lap drives away from the wall. So turn it around one more time:

```
alvik.rotate(180)
```

Now it is standing where it started, pointing where it pointed, ready to go again the moment somebody holds OK.

All three of these behave differently from `drive()`. `drive()` starts the wheels and comes straight back to your program, which is why you needed a loop watching a sensor. `rotate()` and `move()` do not come back until the robot has finished. The line after `alvik.rotate(180)` does not run until the turn is done, and the wheels are already stopped when it does.

That is why the end of your program is three plain lines, with no loop and no `brake()` between them.

# Part 2: Do the work

## Step 1: Set up

1. Turn on your Alvik robot and connect it to your Mac with the USB cable.
2. Open `p04_drive_to_the_wall_and_back.py` in Thonny and save your own copy to the robot as described at the top of this guide. **Name it `p04.py`.** Thonny offers you the long name; change it.
3. In Thonny, open the robot's `main.py`. It is on the robot itself, not inside `workspace`.
4. Replace what is in it with this one line, and save:

```
import workspace.p04
```

5. Clear a run of floor about two meters long, ending at a wall. A real wall, a box, or a book standing up all work.

## Step 2: Type in WORK 1

The loop and the go signal. Until this works, do not let the robot near the edge of anything.

Find the `# WORK 1` comment. Type these lines where the `pass` line is, then delete the `pass` line:

```
while not sb.held('cancel'):
    sb.light_both_leds(1, 1, 1)
    time.sleep(0.25)
    sb.light_both_leds(0, 0, 0)
    time.sleep(0.25)

    if sb.held('ok'):
        pass
```

That last `pass` is a placeholder holding the `if` open until you have something to put in it. WORK 2 replaces it.

Run it from Thonny. Both lights should flash white. Hold Cancel and it stops. Hold OK and nothing happens yet, which is correct.

Now test the part that matters. Unplug the USB cable, turn the robot off, and turn it back on. It should start flashing on its own, with no laptop anywhere. That is `main.py` doing its job.

If nothing happens, one of three things is wrong: the line in `main.py`, the folder your file is in, or the name of your file. Check the name first.

## Step 3: Type in WORK 2

Now it drives. Put the robot on the floor before you run this.

Find the `# WORK 2` comment. These lines go **inside** the `if sb.held('ok'):` block from WORK 1, so they are indented one step further than the `if`. Type them where that second `pass` is, then delete it:

```
alvik.reset_pose(0, 0, 0)
alvik.drive(DRIVE_SPEED_CMS, 0)

while sb.get_closest_distance() > WALL_THRESHOLD_CM:
    time.sleep(0.03)

alvik.brake()
time.sleep(0.5)
```

Press Backspace once before you type `alvik.brake()`. It comes after the `while` loop, not inside it, and so does the sleep under it.

Run it and hold OK. The robot pauses about a second before it moves, which is normal. Then it should roll straight at the wall and stop about fifteen centimeters short. The lights start flashing again when it is done.

Move the robot closer and go again. Move it further back and go again. It should stop about the same distance from the wall each time, wherever it started. If it stops early, look for what else is in front of it.

## Step 4: Type in WORK 3

The trip home, and the turn that gets it ready for the next one.

Find the `# WORK 3` comment and type these underneath your WORK 2 lines, at the same indent:

```
distance_out, _, _ = alvik.get_pose()
sb.log_info(distance_out)

alvik.rotate(180)
alvik.move(distance_out)
alvik.rotate(180)
```

Run it with the cable in first, so you can read the distance in the Shell.

Put a piece of tape on the floor at the robot's front edge before you hold OK. A perfect lap brings that same front edge back to the tape, facing the same way it started.

Run it. Measure how far off the front edge is, and write the number down.

Now run it three more times without touching the robot. Does it drift a little further off on every lap, or does it come back to the same place? That answer tells you something real about how the robot counts.

## Step 5: Worksheet and check off

One run shows everything. Power the robot up with no cable, watch it flash, hold OK, and let it drive to the wall and come back on its own. Do it twice without touching the robot, then hold Cancel to stop.

## FLEX: The A+

This one is not printed anywhere. You work it out.

Your robot has a small screen. `sb.log_info()` already throws the bare number up there, which is not much use to anybody reading it across a room.

Put the distance on that screen properly: a label, the number, and its units, so somebody who has never seen your code can walk up and read what the robot measured.

`sb.update_display()` takes up to three lines of about sixteen characters each.
