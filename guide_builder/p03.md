# Part 1: How it works

Read this part when you get stuck. It has the answer to almost every question you will have.

## 1. Tank drive

A car steers with a steering wheel. A tank does not. A tank has a motor on each side, and it turns by running one side faster than the other.

Your robot drives the same way. That is why this is called tank drive.

- Both sticks forward, and it goes straight.
- Push the left stick further than the right, and it curves right.
- Left stick forward, right stick back, and it spins in place.

Nothing in your code will say the word "turn." A turn is just two wheels doing different things.

## 2. A new SuperBot tool

You already know `sb = SuperBot(alvik)` from P01, where you used `sb.held('cancel')` to end the loop. This project adds one more tool from the same toolbox.

It is `sb.log_info()`. Give it any values and it prints them to the Thonny Shell and puts them on the robot's little screen at the same time:

```
sb.log_info(4, 7)
```

That is the whole tool. Everything else in the toolbox can wait.

## 3. What the sticks report

You already know this loop from P01:

```
while not (alvik.get_touch_cancel() or gamepad.buttons['options']):
    gamepad.update()
```

`gamepad.update()` asks the controller what it is doing right now. Leave it out and you read the same stale numbers forever.

After the update, two values are ready for you:

```
gamepad.left_y     # the left stick
gamepad.right_y    # the right stick
```

Each one is a decimal between -1.0 and +1.0.

- All the way forward: +1.0
- Let go, centered: 0.0
- All the way back: -1.0

Halfway forward is about +0.5. The stick reports how far you pushed it, not just which way. Looking at those numbers for yourself is WORK 1.

## 4. One press, one reading

Your loop runs about fifty times a second. If you print inside it, you get fifty lines a second and the Shell turns to soup.

So your file has a helper already made:

```
btn_x = Button(x_is_down)
```

`btn_x.is_pressed()` is True only at the *instant* you push X down. Hold the button and it is True once, not two hundred times. Let go and press again for a second reading.

That is why WORK 1 looks like this:

```
if btn_x.is_pressed():
    sb.log_info(...)
```

One press, one line of output.

## 5. Sticks and wheels speak different languages

The stick says +0.5. The motor has no idea what that means. Motors want RPM, which is rotations per minute. Ask for 70 and the wheel spins 70 times a minute.

So you translate. You multiply:

```
target_rpm = stick_value * MAX_RPM
```

`MAX_RPM` is already set to 70 in your file. That is as fast as these motors go. Push the stick halfway to +0.5 and you get 35 RPM. Push it all the way to +1.0 and you get the full 70.

Here is the nice part. The minus sign takes care of itself. Pull back to -1.0 and the math gives you -70, and a negative RPM means the wheel turns backward. You never write any code for reverse. It comes free.

## 6. Sending the speeds to the wheels

One line drives both wheels:

```
alvik.set_wheels_speed(left_speed, right_speed)
```

Left first, right second.

Call it every time through the loop. The wheels keep doing whatever you told them last. Stop calling it and the robot keeps rolling.

## 7. The finally block, now with motors

You met `finally` in P01. Code inside it always runs. Normal ending, crash, or Stop button.

It matters more now. In P01 a crash left your lights stuck on. In this project a crash leaves the wheels spinning, and the robot drives off the table.

So the first thing in your cleanup is this:

```
alvik.brake()
```

That stops both motors.

The last line, `alvik.stop()`, is already written for you. Leave it there. It shuts down the robot software and frees the WiFi network. Your cleanup goes above it.

# Part 2: Do the work

## Step 1: Set up

1. Turn on your Alvik robot.
2. Open `p03_gamepad_driving.py` in Thonny and save your own copy to the robot, as described at the top of this guide.
3. Run the program. Thonny prints your robot's WiFi name in the Shell.
4. Connect your Mac to that WiFi network. The password is `password`.
5. Open `http://192.168.4.1` in Chrome. Keep that Chrome window in front for the whole project. Chrome blocks gamepad input to any window that is not focused.
6. Pair your PS5 controller to the Mac over Bluetooth. The robot's LEDs turn green when it connects.
7. Put the robot on the floor. Not on a table.

## Step 2: Write your code

Look for the `# WORK` comments in your Python file. Do them in order.

WORK 1 is looking before driving. Inside the loop, print both stick values when X is pressed:

```
if btn_x.is_pressed():
    sb.log_info(gamepad.left_y, gamepad.right_y)
```

Now run it and read the numbers. Push a stick all the way and press X. Push it halfway and press X. Let go and press X. Write down all three. You should see the full push land near 1.0, the half push near 0.5, and the centered stick sit at exactly 0.0.

WORK 2 is the driving, and it is three lines. Turn each stick value into a wheel speed, then send both:

```
left_speed = gamepad.left_y * MAX_RPM
right_speed = gamepad.right_y * MAX_RPM
alvik.set_wheels_speed(left_speed, right_speed)
```

Drive it. Straight, curving, spinning in place, backward.

WORK 3 is the cleanup, inside `finally:`. Two things, both above the `alvik.stop()` line.

- Call `alvik.brake()`.
- Turn both LEDs off.

Test it by pressing Options while the robot is rolling. The wheels should stop right where they are.

## Step 3: Worksheet and check off

One run shows all of it. Press X a few times and read your numbers out of the Shell, then drive forward, back up, spin in place, and press Options to stop clean.

## FLEX: The A+

Make each LED report on its own wheel.

- That wheel going forward: the LED on that side is green.
- That wheel going backward: red.
- That wheel stopped: white.

The left LED watches `left_speed`. The right LED watches `right_speed`. Use an `if` / `elif` / `else` chain like the one you wrote in P01, and write it twice, once per side.

You do not need to worry about a stick that is *almost* centered. `gamepad.left_y` reports a resting stick as exactly 0.0, so plain `> 0` and `< 0` tests are enough and the `else` catches stopped.
