# Part 1: How it works

Read this part when you get stuck. It has the answer to almost every question you will have.

## 1. No gamepad this time

P01 needed WiFi, Chrome, and a paired controller. This one needs none of that. Plug the robot into your Mac with the USB cable and run it.

You are using the same two lights as P01, and the same `set_color(r, g, b)` command, with 0 or 1 for each color.

## 2. You have been calling functions all along

A function is a named block of code that does a job. You use it by writing its name with parentheses after it. That is called calling the function.

You called three of them in P01 without anyone saying the word:

```
alvik.begin()                       # wakes the robot up
alvik.left_led.set_color(1, 0, 0)   # sets a light to red
time.sleep(0.5)                     # waits half a second
```

The values inside the parentheses are called arguments. They are how you tell the function what you want. `set_color(1, 0, 0)` means red. `set_color(0, 0, 1)` means blue. Same function, different arguments, different result.

Some functions need no arguments. `alvik.begin()` has empty parentheses because there is nothing to tell it.

You do not have to know how a function works inside to use it. You have been turning lights on for a whole project without ever seeing the code that does it.

## 3. both_leds: one call, two lights

Setting both lights took two lines in P01:

```
alvik.left_led.set_color(1, 0, 0)
alvik.right_led.set_color(1, 0, 0)
```

Your file has a shortcut already written near the top:

```
def both_leds(r, g, b):
    alvik.left_led.set_color(r, g, b)
    alvik.right_led.set_color(r, g, b)
```

`def` is short for define. Those lines do NOT run when Python reads them. They sit there, waiting. They only run when you call `both_leds(...)` somewhere below.

The `r`, `g`, `b` in the first line are catchers. When you call `both_leds(0, 1, 0)`, Python catches 0 in `r`, 1 in `g`, and 0 in `b`, then runs the two lines using those values.

So `both_leds(0, 1, 0)` turns both lights green, in one line instead of two.

## 4. What a blink actually is

A blink is four steps, in order:

- Turn the lights on.
- Wait.
- Turn the lights off.
- Wait again.

Miss the second wait and there is no blink. The lights go off and instantly back on, far too fast to see. Your eye reads it as dim, steady light.

To blink more than once, wrap those four steps in a loop that counts:

```
for _ in range(3):
    both_leds(1, 0, 0)   # on, red
    time.sleep(0.5)      # wait
    both_leds(0, 0, 0)   # off
    time.sleep(0.5)      # wait
```

Change the 3 to a 20 and it blinks twenty times. The loop does the counting for you. That is WORK 1.

## 5. blink: the whole thing in one call

Your file has a second function already written for you. It is that entire loop, packed up:

```
def blink(blinks, on_time, off_time, r, g, b):
    for _ in range(blinks):
        both_leds(r, g, b)
        time.sleep(on_time)
        both_leds(0, 0, 0)
        time.sleep(off_time)
```

Six arguments this time, so it needs six values. To blink red three times, half a second each way:

```
blink(3, 0.5, 0.5, 1, 0, 0)
```

That one line does everything WORK 1 does by hand.

Look at the ladder you now have. `set_color` sets one light and came from Arduino. `both_leds` sets two lights and calls `set_color` twice. `blink` runs a whole pattern and calls `both_leds` over and over. Each one wraps up the one below it so you can say more with less typing. In P04 you write your own.

## 6. Variables: Name it once

That `blink(3, 0.5, 0.5, 1, 0, 0)` line works, but look at it. Six bare numbers in a row. Which one is the color? Which is the speed? You have to count positions to find out.

A variable is a name for a value. You write the value once and use the name after that:

```
on_time  = 0.5
off_time = 0.5
r = 1
g = 0
b = 0

blink(3, on_time, off_time, r, g, b)
```

Now the line reads like a sentence. And here is the part that matters: change a variable, and the same call does something different. Set `r = 0` and `b = 1` and that identical `blink(...)` line blinks blue instead of red.

Programmers have a rule about this: never type the same number twice. Name it once instead.

## 7. The show repeats until you press Cancel

Everything you write sits inside a loop from P01:

```
while not alvik.get_touch_cancel():
```

Read it out loud: while Cancel is NOT touched, keep going. So your three light patterns play, then play again, over and over, until you touch the X button on the robot. No Thonny Stop button needed.

# Part 2: Do the work

## Step 1: Set up

1. Turn on your Alvik robot.
2. Connect it to your Mac with the USB cable.
3. Open `p02_flashing_lights.py` in Thonny and save your own copy to the robot, as described at the top of this guide.

## Step 2: Write your code

Look for the `# WORK` comments in your Python file. Do them in order. All three go inside the `while` loop, one after another.

WORK 1 is the blink by hand. Inside the `for` loop, write the four steps: on, wait, off, wait. Red, half a second each way.

WORK 2 is where the real lesson starts. Make five variables of your own and pick your own numbers:

```
on_time  = 0.5
off_time = 0.5
r = 1
g = 0
b = 0
```

Then blink three times using the names, not numbers:

```
blink(3, on_time, off_time, r, g, b)
```

WORK 3 is the payoff. Give those same five variables new values. Pick a different color. Make it faster or slower. Then call `blink` again with a line that is character-for-character identical to the one in WORK 2.

Two calls that look exactly the same, doing two different things, because the variables changed in between.

## Step 3: Worksheet and check off

One run shows all three, in order, over and over until you touch Cancel: three red blinks by hand, then your WORK 2 blink, then your WORK 3 blink.
